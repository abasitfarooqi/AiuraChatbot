Unified Configuration

This is the central configuration file for your chatbot. All settings including business info, company details, prompts, chatbot service settings, and application config are managed here. Perfect for multi-vendor and multi-business use!

Switch between versions or create new ones. "Current" is the active version in use.
Key Sections:
• business - Company name, services, branches
• contact - Phone, email, contact format
• prompts - System prompts (use variables like {company_name}, {contact_email})
• chatbot_service - Greetings, suggestions, topic detection, response formatting
• application - API settings, database, embedding, LLM config

Variables available: {company_name}, {company_name_lower}, {contact_phone}, {contact_email}, {services_list}, {primary_service}, {contact_format}

Cache Management

Manage Q&A caching to reduce LLM usage and optimise costs. Main cache is persistent per vendor, temporary cache is per chat session.

Cache Control

ON: Use cached answers when available (saves LLM costs)
OFF: Always use LLM to generate fresh responses (no cache lookup)

ON: If question not in cache, use LLM to generate answer
OFF: If question not in cache, return "not in cache" message (no LLM call)

⚠️ TESTING MODE: When ON, LLM is completely disabled. Only cache responses will be used.
ON: Cache-only mode (NO LLM calls, perfect for testing cache performance)
OFF: Normal mode (LLM available when needed)

ON: Use a lightweight/cheaper model (e.g., Ollama) when generating responses that will be saved to cache
OFF: Use the default/main LLM model for all responses

Select Cache Model (Lightweight LLM)

Select a lightweight model (e.g., Ollama) to use when generating responses that will be cached. This saves costs while maintaining quality for cached responses.
